**Sthira — design, navigation, UX and functional audit**

Reviewed 8 September 2026. Source: the supplied `Sthira-Without-Mitra-main (6) (1).zip`.

**Verdict**

Home and Today's Meals provide a useful visual foundation: calm surfaces, prominent numbers, compact supporting information, and simple navigation. That foundation is not applied consistently across the app. The most urgent problems are functional: overwritten workout entries, incomplete Progress metrics, misleading Social results, restore-state failures, and controls whose labels promise actions they do not perform. Correct these before adding animation.

The app already contains substantial motion. My recommendation is to reduce decorative repetition and retain short feedback that explains a user's action.

**Scope and limits**

This is a source audit of all **58 Dart files under `lib/screens`**, including screen-local widgets, dialogs and sheets; the router, shared controls, theme, and relevant repositories/providers were also inspected. This is not 58 independent navigable pages. Some files are unused components, identified below. The inventory is in [ui-audit-evidence.json](D:/from/boyd/meal-ai-audit-20260908/ui-audit-evidence.json).

Flutter and Dart are not available on PATH in this environment. I did not build or launch the app, inspect rendered screenshots, measure frame times, run TalkBack/VoiceOver, or exercise a live backend. Findings marked **confirmed** follow directly from source or a small deterministic arithmetic reproduction. Items marked **verify** are plausible runtime risks, not observed crashes or visual overflows. Recommendations are design judgments.

The user confirmed that `sthira_design_system.md` is the intended reference. I used [that document](D:/from/boyd/meal-ai-audit-20260908/Sthira-Without-Mitra-main/sthira_design_system.md:1). It contains legacy Sasirekha branding and an outlined-pill instruction that conflicts with the user's explicit borderless requirement; **the user's no-borders instruction takes precedence**. Home and Today's Meals are references for hierarchy and visual character, not exemptions from bug fixes or consistency checks.

The earlier [meal AI audit](D:/from/boyd/meal-ai-audit-20260908/MEAL_AI_AUDIT.md) remains applicable. This document adds the wider product review.

**One shared visual standard**

| Element | Adopt across the app |
|---|---|
| Surfaces | Keep the forest scaffold, gently lighter card surface, warm text and peach accent from the existing palette. Use spacing and filled surfaces to separate information. No card outlines, outlined chips, bordered error boxes, or decorative divider rules. |
| Card geometry | Prefer the design document's 24 dp main-card radius and 20 dp internal padding. The current shared radius is 20 while several custom cards are 24; consolidate into one token. Keep input/button/sheet radii separate because they are different controls. |
| Hero summaries | Use a short label, prominent value with an explicit unit, target/period context, and at most one thin progress track where it answers a question. Preserve Home/Meals' typography-led hierarchy. Do not turn every metric into a hero or add gauges/rings to ordinary summaries. |
| Tiles | Reuse one accessible navigation tile with leading content, flexible title/subtitle, optional trailing value, and an unboxed chevron. Make the entire tile tappable when it has one destination. Avoid independent large-card scaling. |
| Chevrons | Standardize navigational rows on `Icons.chevron_right_rounded`, with a shared size/color token. Home currently uses larger chevrons; scanner uses `arrow_forward_ios_rounded`; Profile uses another size. Use the left-facing equivalent for back and down/up for expansion. The bottom bar itself uses destination icons, so preserve those icons and their selected state. |
| Action meaning | A chevron opens something. A switch changes a setting. A check confirms a state. Keep the chevron if a completed card still opens details; put its completion check beside its status. Remove chevrons from unavailable/no-op rows. |
| Type | Cabinet Grotesk for headings and prominent numbers; General Sans for body, controls and supporting copy. Fix the scanner's `CabinetGrotesk` spelling to the registered family. Reduce one-off font sizes and promote meaningful 9–11 px text to a readable secondary style. |
| Sections | Use the existing uppercase peach SectionHeader, integrated counts, and consistent spacing. Allow the title to flex/wrap when there is a trailing action. Avoid adding section labels where a simple list is clearer. |
| Inputs | Filled fields with no visible border in normal, focused or error states. Preserve clear focus with a stronger fill/caret/label change and errors with inline text plus an icon. The shared `AppTextField` is already borderless; global InputDecorationTheme is not. |
| Choices/actions | Borderless tonal segments and secondary buttons. Selected fill plus check/semantics, not color alone. Preserve destructive text meaning without a red outline. |
| Sheets | Standardize the existing AppSheet helper: keyboard-aware maximum height, scrollable content when necessary, one handle, 24 dp top radius, one owner of safe-area padding, clear primary action and dismiss behavior. Current custom sheets vary between 24 and 32 dp and duplicate insets. |
| Feedback | A consistent in-progress state, successful persistence feedback, actionable error and retry. Do not show “Connected”, “Verified”, “Saved”, or “Syncing” merely because a local boolean changed. |
